# ChronoShift: AI lab and infrastructure design research

Observed 7 October 2026 in Australia/Sydney (6 October UTC), using seven first-party websites in the Codex in-app browser. Desktop captures were taken at 1280 × 720. This is a qualitative design survey, not a traffic ranking or a usability study. Computed DOM values are evidence at that viewport, not complete vendor design systems. Proprietary fonts and imagery are references only; prototypes use the existing locally bundled Geist and system Georgia.

## Design rules for ChronoShift

The following rules are proposed adaptations from the survey and the existing product contract. They are not claimed vendor guidelines or experimentally proven preferences.

**Information hierarchy.** The user should locate the message input, destination zone and converted time immediately. Keep original text and assumptions close to the result, with less visual weight. Group by source match; preserve meaningful alternatives. Range endpoints belong together wherever the engine provides an unambiguous relationship. Do not expose the internal start/end enum values as labels.

**Layout.** Try three architectures, not three colour skins: an asymmetric two-column editorial workbench; a bounded input rail alongside a wide output area; and a centered composer with results below. At narrow widths, stack in reading order without replacing the current draft. Keep the destination in the input flow and its name repeated above output. Avoid sidebars with invented navigation or dashboards unrelated to conversion.

**Typography.** Use the existing locally bundled Geist for controls, body and numerals. Use system Georgia only where a direction benefits from editorial contrast. Proposed desktop headline range 54–76px, body 16–18px, input 18–20px, output 48–66px, context 12–14px. At 280px, reduce output to about 32px and allow natural wrapping, including seconds/milliseconds and clock suffixes. Use tabular numerals for time. Prefer clear weight/size differences over many fonts or all-caps text. Tiny eyebrow copy is decorative hierarchy, not the only explanation of a control.

**Spacing.** Use a 4/8px rhythm: 16–24px control groups, 24–32px panel insets, 32–56px major sections. Proposed max work width about 1160px; centered canvas about 820px. On small screens, 16–22px page gutters leave space for real input and results. Avoid copying large marketing hero gaps into a frequently used utility.

**Colour.** Build on neutral surfaces with one accent. Use strong contrast for the result, muted text only for genuinely secondary context. Do not treat green as proof of correct interpretation. Show ambiguities explicitly in words. Give light and dark alternatives their own measured contrast choices; colours alone never distinguish a range, assumption or error.

**Surfaces and borders.** Use whitespace and hairlines for repeated rows. In the editorial direction, one softly tinted result area establishes hierarchy. In the console, a clear divider separates input from output. In the focus direction, one bounded composer is the main surface; result groups use quieter shells. Choose a coherent radius vocabulary per direction instead of rounding every element identically. Avoid nested cards, excess shadow and gratuitous glass blur.

**Controls.** One matching label per input; accessible names must reflect the same vocabulary. Use native keyboard-operable controls for these prototypes, with visible focus, roughly 44px targets and 16px-plus editable text. Prototype zones are intentionally a small list; production retains the supported searchable zone/city control. Progressive disclosure should make optional interpretation controls understandable, rather than bury important assumptions.

**Writing.** Task-first and concrete: “Paste a message. Get the times where you are.”; “Convert to”; “Source time zone”; “Message date”; “Date format”; “Time format”; “Copy”. Source help: use the device zone when the message has no zone; explicit input takes priority. Message-date help: today by default, or the date of an older message to interpret “tomorrow”. Date format describes reading numeric input; time format describes display/copy output. Keep useful dates, offsets, DST alternatives and assumptions. Replace implementation terms such as “Unix seconds” in result labels with relevant context.

**Imagery.** The surveyed sites use imagery to tell a product/research story. ChronoShift's useful visual is the conversion itself. No stock AI gradients, network diagrams, vendor logos or decorative model imagery are needed in the work area. A tiny typographic brand mark and well-composed times can supply identity.

**Motion.** The later motion research below and the approved spec supersede this survey's initial limited motion guidance. Include a finite workspace entrance, small result reveal and polished controls/disclosure/popovers/theme/copy interactions. Preserve immediate usability, stable numerical text and reduced-motion behavior.

## Three prototype directions

All palette values below are original proposed tokens, not copied vendor tokens. All three prototypes use the actual local conversion engine and offer message input, destination changes, range/ambiguity/relative-date samples, source/reference correction, date/time preferences, clear action and copy fallback. They do not implement the full worker/PWA/share/update lifecycle and must not be promoted to production without the implementation gate.

| Direction                   | Palette and type                                                                                  | Structure                                                                                                              | Tradeoff                                                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **A — Editorial workbench** | Paper #f7f4ed, warm panel #eee8dd, ink #29251e, clay #8e4029. Geist plus a Georgia italic phrase. | Strong left-aligned opening; message and controls left; tinted result area slightly wider on the right.                | Most distinctive and welcoming. Larger opening uses more vertical space; compare practical scanning on phones.                          |
| **B — Signal console**      | Forest #0c120f, field #101a14, text #e7eee8, muted #a1b3a5, lime #b2ed89. Geist, tabular output.  | Compact two-part intro; bounded 350px input rail; large results separated by hairlines.                                | Best for repeated desktop conversion and technical clarity. More dense; ensure small screens still feel open.                           |
| **C — Focus canvas**        | Cool #f6f8fc, white surfaces, ink #182335, blue #244ea8, border #d6ddeb. Geist throughout.        | Centered task heading; one large composer; destination and optional controls within it; full-width results underneath. | Simplest first-use flow and strongest mobile continuity. More vertical scanning on desktop; less simultaneous source/output comparison. |

Each direction includes a light/dark toggle to compare contrast treatment. These are visual alternatives, not a final decision about the shipped default or theme persistence. Shortlisting in the gallery stays in that open page; it does not send or save a selection remotely.

## Linear component refinement — 7 October 2026

The user selected A and B and requested rounded/curved components inspired by Linear. Inspected [Linear’s homepage](https://linear.app/) and [public login form](https://linear.app/login) in IAB; no credentials entered or form submitted.

Observed computed styles: homepage Sign up is 32px high with a 9999px radius; Get started and Contact sales are 44px high with pill radii. Public app demonstration label controls have 16px radii and 24px heights. The email input has a 10px radius, 12px padding and a 0.5px border; its measured height during the form transition was about 43.2px. Continue with email is pill-shaped. These are observations of these public surfaces, not an official universal Linear design-system specification.

Applied ChronoShift tokens: pill action buttons and example selector; 10px rectangular select/input corners; 16px multiline input corners; 24px major panel corners; thin borders and restrained inset highlights. Preserve 44px minimum control targets rather than copying the compact demonstration sizes. A retains its warm editorial split and serif accent. B retains forest/lime and its compact input rail, now inside a curved workspace. C is retained locally as an earlier candidate but removed from the active comparison gallery. A+B are selected by default.

Author IAB validation of this CSS/gallery refinement: desktop plus 280px/390px settings-open views for both A/B; all visible controls at least 44px high, no horizontal overflow (iframe client/scroll 278/278 and 388/388). Build and targeted formatting passed; engine behavior unchanged. Evidence is in .work/[TIE-383](https://github.com/Tien-Lam/time-to-local/issues/107)/qa/_rounded_. Initial independent review reports refer to their original source hashes; this small presentation delta has author browser evidence.

## Linear’s application controls and editor hierarchy

Expanded the research beyond marketing CTAs, using the [public application demonstration](https://linear.app/), [issue-creation documentation and screenshot](https://linear.app/docs/creating-issues), and [editor documentation](https://linear.app/docs/editor). The authenticated ticket page requires login in this IAB session, so no claim is made about measuring that live private editor.

Measured public demonstration: issue title 20px / 26.6px, weight 590, tracking -0.24px, no individual border/background; description 14px / 21px, weight 400, muted text, no separate box. The actual rendered public workspace menu is an 8px rounded surface with a subtle 1px border; rows are 13px with 12px horizontal padding. The issue-creation screenshot shows a shared editor surface, stronger title above flowing description text, compact rounded rectangular property controls and a rounded rectangular primary action. Exact pixels in this screenshot are not claimed as computed CSS.

Linear’s editor docs explain that formatting controls appear with text selection or slash commands. Transfer the quiet, contextual interaction pattern to ChronoShift's plain-text message task; do not add rich-text formatting, mentions, attachments, or extra title fields without a product need.

Final A/B application refinement supersedes the initial all-pill actions: 8px rounded rectangular Copy/Reset/Clear/example controls, 10px property fields, 16px editable-region corners, 24px shared editor/workspace surfaces. Theme switch remains a pill. Message title hierarchy is 20px/1.33/590; description-like message text is 16px/1.5, relaxed from Linear’s denser demo for readable input. Resting editor text flows on a unified surface, with a quiet hover border and explicit keyboard focus. Disclosure uses a chevron and rounded hover row. All controls retain 44px targets. A retains editorial identity; B retains compact console identity.

Latest validation: Bun build/format passed; author IAB desktop plus 280/390px settings-open A/B views have no overflow and 44px minimum visible controls. Keyboard Tab reaches the example selector with a 2px focus outline; Enter opens the disclosure with a rotated chevron and visible outline. Evidence: .work/[TIE-383](https://github.com/Tien-Lam/time-to-local/issues/107)/qa/_editor_ and .work/[TIE-382](https://github.com/Tien-Lam/time-to-local/issues/106)/references/linear-issue-composer.jpg, linear-menu.jpg. Engine JavaScript unchanged. Prior independent reports remain bounded to their original source hashes.

## Motion and interaction research — 7 October 2026

The user requested animations and interaction polish for the approved A/B designs. Revisited all seven original AI references plus Linear in background IAB tabs. The measurements below come from rendered DOM/computed CSS on public pages, including opening the Linear, Modal and Anthropic navigation menus. They are bounded examples, not official design-system rules. Animation declarations alone do not prove visible playback, frame rate or reduced-motion compliance.

| Reference                                   | Observed motion                                                                                                                                                                                                                                                                           | Adaptation for ChronoShift                                                                                                                                                                                                                                    |
| ------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Linear](https://linear.app/)               | Navigation colour/background transitions 100ms; public app-demo controls commonly 160ms with cubic-bezier(0.25, 0.46, 0.45, 0.94). Opened navigation popup declares an 180ms scale-in animation and 220ms width/height transitions. Decorative marquees 30s and grid dots 2.8s repeating. | Primary reference for quick control feedback and anchored popovers. Use short, small-distance motion; keep message text and numerical results stable.                                                                                                         |
| [Modal](https://modal.com/)                 | Navigation colour transitions 150ms; menu links have 200ms opacity transitions. Page artwork uses canvases; CSS includes a 3.2s ease-in-out glow pulse, 120s marquee and 5s carousel progress. Rendered classes distinguish motion-safe/motion-reduce behavior.                           | Give B a restrained accent reveal and responsive controls. Borrow the coordinated rhythm; use a finite accent gesture when meaningful rather than carrying the homepage loops into the tool. Reduced-motion classes were observed, not functionally verified. |
| [Anthropic](https://www.anthropic.com/)     | Links typically 200ms colour transitions; opened research dropdown declares 400ms opacity transition and nested text 100ms.                                                                                                                                                               | Soft surface changes fit A's warm palette; task menus should settle faster than the marketing dropdown.                                                                                                                                                       |
| [Baseten](https://www.baseten.co/)          | Initial title CSS reveal 800ms; CTA transitions 236ms with cubic-bezier(0.5, 0.2, 0.4, 1); status icons declare 2s opacity pulse.                                                                                                                                                         | A finite page entrance can establish craft, but shorten it and keep the editor immediately usable. State feedback must reflect actual conversion/copy events.                                                                                                 |
| [Together AI](https://www.together.ai/)     | Links declare 350ms transform/colour/opacity and 450ms shadow transitions; hero/research strips declare 30s horizontal loops.                                                                                                                                                             | Use continuity between states and a quieter depth change. Avoid the long marketing timings for frequently used controls.                                                                                                                                      |
| [Replicate](https://replicate.com/)         | Catalog links 150ms colour transitions; 90s moving groups and autoplay/loop video elements in the catalog.                                                                                                                                                                                | Keep action feedback quick and preview behavior tied to a real task. ChronoShift's equivalent is a readable result reveal, with no media dependency.                                                                                                          |
| [Google DeepMind](https://deepmind.google/) | Navigation links declare 200ms shadow/colour transitions. Multiple autoplay/loop video elements; no CSS animation names in this sampled DOM.                                                                                                                                              | Restrained hover depth and clear interactive affordances. Playback and JS/scroll animation behavior were not measured.                                                                                                                                        |
| [OpenAI](https://openai.com/)               | Actual homepage navigation declares 100ms colour transitions and many header actions 200ms transitions. No CSS animation names in the final sample.                                                                                                                                       | Fast, quiet feedback around the message composer. An initial browser challenge animation was excluded after the actual site loaded.                                                                                                                           |

Evidence: .work/[TIE-382](https://github.com/Tien-Lam/time-to-local/issues/106)/references/motion/observations.json and Linear/Modal menu captures. This pass did not profile performance, emulate reduced motion, verify private application controls, or systematically test vendor scroll animations.

The approved spec's “Motion and interaction” section is the implementation contract. This supersedes the earlier research paragraph limiting motion to colour/opacity: the design now includes a finite workspace entrance, small result reveal, disclosure/popover transitions, theme changes, hover/press feedback and truthful copy confirmation. The approved compact header and absence of hero/title/description remain unchanged.
