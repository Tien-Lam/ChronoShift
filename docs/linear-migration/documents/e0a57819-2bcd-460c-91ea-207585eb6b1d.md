## Page structure

- Compact header: small clock mark and ChronoShift name on the left, theme control on the right. Prototype height 65px, theme target 44px. Align header and workspace horizontal gutters.
- No visible hero title, promotional tagline, introductory description, or result eyebrow.
- The workspace follows immediately: editable message, example/clear actions, target-zone control, collapsed interpretation/format settings, and prominent converted results.
- Footer contains the short privacy note. Do not duplicate branding/theme controls in the footer.
- Keep functional “Message” and destination headings, input labels and a visually hidden accessible page heading.

## Components and typography

Use bundled local Geist for interface text. A's result destination heading uses a restrained Georgia serif accent. Do not load remote fonts.

Homepage pill CTAs are a separate reference; task actions use the application's rounded rectangle treatment. ChronoShift remains a plain-text conversion utility.

## Options and results

Integrate existing Options Clarity work in [TIE-379](https://github.com/Tien-Lam/time-to-local/issues/103), [TIE-380](https://github.com/Tien-Lam/time-to-local/issues/104) and [TIE-381](https://github.com/Tien-Lam/time-to-local/issues/105) (PR #45) rather than reimplementing it. Preserve its verified parsing/display semantics and corrections.

Date/time labels must be consistent and explain input date interpretation versus output time display. Source zone is a fallback when input omits a zone; reference date anchors relative/incomplete dates. Keep device/today defaults and correction paths clear.

No raw start/end enums or implementation-only tags in visible results, copy text or accessible names. Preserve range association/order, overnight rollover, mixed-zone endpoints, DST alternatives, precision and useful assumptions. Do not confuse range endpoints with alternative interpretations.

## Responsive behavior

Retain both editor and results without losing input or preferences through resize. Stack gracefully on narrow screens; no page, header, field, or footer overflow at 280/390px. Keep long times and subsecond numerals intact; move Copy below when needed. Expanded settings, ambiguity, ranges, empty/error states and fallback copy must fit.

## Production acceptance

Preserve offline/local-only conversion, input/reference-date privacy, independent source/target, explicit ambiguity, PWA base path /ChronoShift/, theme/preferences reset, import and clipboard focus, resize state and updates activated only by user action.

Run repository check/format/build and appropriate browser/Playwright gates. Exercise source/reference validation and rapid edits, all conversion classes, light/dark/system, clipboard success/failure, offline/service worker/update and deployment subpath. Two clean-context independent reviewers must review surrounding lifecycle paths, per docs/developer/review.md. Record implementation and original-report verdicts separately; preserve gaps.

Prototype evidence is author IAB desktop/narrow plus bounded source/artifact reviews. The independent prototype reviewers lacked IAB; later presentation deltas have author QA. This approval covers the design, not full production/PWA readiness. Physical-device testing remains outside scope.

## Motion and interaction

User addition on 7 October 2026: “designs should have animations, etc. look at those websites for reference too”. Motion is required in the A/B redesign, with the same interactions and timing vocabulary across both palettes. This extends the approved static design; the attached prototype archive/screenshots predate this motion requirement and are visual references, not a finished animation demo.

Research: [motion observations in the design research](https://github.com/Tien-Lam/time-to-local/blob/main/docs/linear-migration/documents/df858fa8-e96d-40d6-8f7c-27be40ed31ef.md). Linear's public controls/popovers are the primary interaction reference; Modal's coordinated accents inform B and the softer Anthropic/Baseten reveals inform A. The following tokens are ChronoShift proposals, not copied vendor specifications.

| Interaction                                            | Proposed motion and trigger                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First workspace entrance                               | One finite opacity/4px upward settle, 320ms; panel stagger at most 40ms, combined completion within 400ms. Header/editor remain usable immediately. Play once per page load, never on every conversion, theme change or resize.                                                                                                                    |
| Buttons, example actions, fields                       | 100–160ms colour/border/shadow feedback. Optional pressed surface/icon displacement at most 1px, with the hit target stationary. Keyboard focus indicator appears immediately. Message text, caret and field geometry stay stationary.                                                                                                             |
| Searchable zone menus and theme popover, where present | 180ms opacity and scale 0.98→1 around the trigger-side origin; close in 120ms. Preserve existing native-control behavior where applicable. Focus, Escape and outside dismissal respond immediately; exiting content must not remain focusable.                                                                                                     |
| Interpretation/settings disclosure                     | Chevron rotation 160ms, content reveal/collapse up to 220ms. Any container-height interpolation must track actual content and finish at intrinsic height; collapsed fields leave the tab order immediately. Rapid reversals must settle to the requested state.                                                                                    |
| New result groups                                      | Once when committed results introduce a genuinely new group: opacity and at most 4px settle over 180ms, stagger at most 30ms and total at most 240ms. Existing numeric text updates atomically and stays readable; do not fade the whole result pane or restart entrance effects on every keystroke. Copy targets must not move under the pointer. |
| Copy success/failure                                   | Show truthful text/state immediately after the clipboard operation outcome. Success icon can draw/settle over 160ms; return to idle after approximately 1.5s. Reserve label width to prevent jumping. Rejection keeps the fallback available; no success animation before success. Status remains available to assistive technology.               |
| Theme change                                           | 200ms surface/text/border colour transition after an explicit user change; first paint and system-theme resolution are immediate. Preserve readable contrast during the transition and all draft/results/focus. Avoid broad transition: all.                                                                                                       |
| Empty, error and ambiguity state changes               | 160–180ms surface/icon feedback without delaying the state text. Keep explanations persistent, accessible and distinguishable without colour or motion.                                                                                                                                                                                            |
| Clock mark/accent detail                               | Optional finite hand/mark settle on initial entrance or theme selection, up to 240ms, in the existing compact mark. A uses a soft clay accent; B can use a brief lime border/accent reveal. Do not add a hero or permanent ticking/pulsing decoration.                                                                                             |

Use a shared ease-out curve, proposed cubic-bezier(0.22, 1, 0.36, 1), for entrance/reveal and a symmetric ease for colour/state transitions. No bounce/overshoot for menus, field controls or time values. Keep decoration secondary to the workspace and use the same motion semantics in A and B.

Respect prefers-reduced-motion: reduce on first load and when it changes while the app is open: eliminate travel, scale, stagger, clock gestures and interpolated disclosure height; render the requested final state immediately. Remove decorative animation and shorten nonessential colour feedback to immediate or at most 50ms. Content, focus, copy confirmation and validation must work identically with animations disabled or unsupported.

Never delay conversion, create artificial loading time or announce success through animation alone. Do not count through intermediate clock values, animate away precision, flash results, or animate controls while someone selects/copies text. Cancel or replace stale animation work during rapid edits, result replacement, resets and unmounts. Prefer CSS transform/opacity for transient presentation; confine necessary disclosure layout work to that panel and avoid expensive filter/blur or perpetual animation loops. Keep all assets and motion code local.

Before delivery, provide an interactive motion preview for both palettes and capture short recordings or a before/during/after sequence of entrance, disclosure, zone menu, result change, copy and theme behavior. Include normal and reduced-motion conditions, narrow/desktop layouts, keyboard and rapid interruption. Static screenshots alone do not establish motion acceptance. [TIE-385](https://github.com/Tien-Lam/time-to-local/issues/109) implements this contract; [TIE-386](https://github.com/Tien-Lam/time-to-local/issues/110) validates it.

## Mobile touch feedback follow-up — 7 October 2026

The user reports a blue square when tapping buttons on mobile. [TIE-387 — Replace mismatched mobile tap highlights](https://github.com/Tien-Lam/time-to-local/issues/111) tracks investigation and correction after the completed redesign. Native browser tap feedback is a likely cause based on the missing tap-highlight override; the exact reported device/browser has not been reproduced.

Touch feedback must use each theme's colours and stay within the rounded control. If native tap highlighting is suppressed, provide visible custom pressed feedback and retain keyboard focus/high-contrast behavior. Audit all task buttons, disclosures, menu choices, calendar/zone controls and tappable links; preserve editing selection, scrolling, cancellation, 44px targets and reduced motion. Save press-time evidence and distinguish browser emulation from physical-device proof. The ticket contains detailed acceptance; completed [TIE-385](https://github.com/Tien-Lam/time-to-local/issues/109)/386 evidence is not retroactively expanded to cover this new report.

## Shared prevention for all design issues — 7 October 2026
