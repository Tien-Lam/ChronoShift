## Proposed causal fix and meaningful coverage

Prefer the public ListBox `shouldFocusOnHover={false}` configuration for ZoneChoice only, leaving generic ChoiceSelect unchanged. Installed ListBoxProps extends AriaListBoxProps and exposes this option; `useOption` then disables hover-driven focus while preserving item press/key selection owners. This removes incidental hover from the commit key, instead of a custom Tab state/event hack or disabling custom input. Candidate still requires independent verification of keyboard ArrowDown/Enter selection, explicit pointer/touch selection, aliases/freeform offsets, typed canonical Tab/blur, source/target independence and invalid-to-valid stale-copy protections.

A meaningful regression must create actual pointer modality **before** alias entry on the unchanged build, assert alias hovered+active descendant osaka while canonical selected/input remains Asia/Tokyo, then show Tab changes the value before the fix. Candidate should keep hovered feedback but reject that focused-alias takeover, retain canonical text and exact date/time/source/copy identity. Hover alone while keyboard modality is active is an insufficient before-control; selected vs focused vs hovered states must be recorded separately. Exact output/source assertions in imports.spec.ts should remain unchanged.
