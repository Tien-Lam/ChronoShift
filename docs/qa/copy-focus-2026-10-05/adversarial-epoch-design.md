# Independent pre-candidate epoch design review

Observation clock: 2026-10-05 09:26:47–09:27:57 UTC. Explicit cwd `/Users/tien/Developer/ChronoShift`. Source `eef0d51ea3ca835dfe27d7e157c6bfad1610a7b3`. Read-only design assessment of root's proposed focus-intent epoch, using local App, Choices, React Aria combobox/press code and StrictMode entry point. No candidate source, tests, API calls, peer verdict or source mutations.

Proposal: while App is mounted, document capture listeners increment a separate ref on focus, pointerdown and keydown. Copy snapshots the ref before awaiting clipboard; its deferred fallback focus requires matching copyRequest and epoch. This keeps import/edit conflict semantics independent. There is no static design blocker to that bounded policy, with the conditions below; runtime acceptance remains unobserved.

Copy is a native button with onClick, not React Aria onPress. The snapshot belongs inside copy after the initiating click's prior pointer/key/focus events. It must not accidentally snapshot before those initiation events. A later RAC programmatic focus/restore is observable new focus: yielding is conservative because another control has obtained focus. It may leave fallback text visible for explicit selection, which its existing onFocus handler supports. Ordinary undisturbed fallback still needs proof in WebKit where pointer activation may leave an earlier input focused.

Focus-generation plus pointer/key activity addresses same-element interaction and focus-away/return without editing. ActiveElement equality can be an additional detached-owner/identity check, but cannot replace the epoch. No-new-event programmatic operations are a limit: focusing an already active element does not produce another focus event, and Playwright fill can insert text without a keyboard keydown. Input invalidation guards an accepted edit, but a pre-insertion automation gap is not automatically represented by the epoch. Record actual initiating focus and event sequence before claiming the original helper is fully protected; there is still no historical first-failure trace.

The manual textarea selects text in onFocus. An allowed frame's own focus therefore increments the epoch. Evaluate guards once before focus/select; rechecking between those operations would mistake its own focus for a competing interaction. Selection itself should not invalidate another copy request. Every newer copy snapshots the latest epoch and increments request identity, so an older frame yields even if its initiating button/field matches the new one. An older settlement should also retain the existing request-identity guard before changing notice/fallback state.

Listeners should be one stable constant-time ref increment each, with no render, permanent storage, diagnostics payload, event suppression or growing event history. Register/remove the same handler with the same capture setting. App's StrictMode development setup/cleanup/setup must leave one effective listener set. Cleanup should invalidate outstanding ownership or requests so an old callback cannot claim a later lifetime; null copyField alone prevents actual focus after an ordinary unmount, but is a weaker lifecycle contract. Detached initiating elements or browser-generated focus during remount should make the callback yield rather than adopting a different element.

Scheduling-control caution: an addInitScript document capture listener can precede the App epoch listener. If that listener synchronously executes a held RAF callback inside a target focus event, it may run before the epoch listener sees that event. A real animation frame runs after event dispatch. Preserve real frame scheduling when releasing a held callback, or explicitly identify the artificial event-listener ordering and use activeElement as an additional check. This is a control-design risk, not another reviewer's result.

Acceptance remains the original focus-contract cases plus ordinary fallback selection, listener cleanup/remount, and event-order evidence for the old-source held-frame reproduction. No motion/hover/timeout/retry/helper changes should be used to hide failure. Implementation verdict: design conditionally suitable; no candidate approved. Original report verdict: unresolved pending controlled equivalent old failure and corresponding candidate proof.
