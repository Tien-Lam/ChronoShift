## Escaped bug and workflow correction

Earlier reviews covered healthy clean profiles, delayed lifecycle state and damaged/retired cache assets. They treated changed HTML bytes as release corruption whose rejection was expected. That was inadequate for an otherwise usable same-release page rewritten by a network content filter. The first detailed user log identifies index.html before any controller, distinguishing this failure from earlier retained-cache hypotheses. Reviewers are not being credited with resolving an unknown user profile based on clean-profile success. The review workflow and regression suite now explicitly distinguish response-level HTML rewriting from DOM-only modification, and verify canonical shell generation/recovery alongside unrelated asset rejection. Brief recording occurred after initial dispatch this time; the limitation is explicit, and future briefs must be saved before dispatch as the workflow already requires.
