## Virtualization feasibility and risks

The installed package publicly exports **Virtualizer** and **ListLayout** from `react-aria-components/Virtualizer`; no dependency installation is needed. Its declared `VirtualizerProps` accept a child collection such as ListBox, a layout class/object, `layoutOptions` and `shouldObserveItemSize`. Installed implementation supplies a virtual collection renderer, layout delegate, scroll ref and persisted keys. ListBox consumes that context for keyboard navigation and marks itself virtualized; persisted keys include the focused key. ListLayout supports fixed `rowSize` or variable `estimatedRowSize`; deprecated `rowHeight` names should not be used in a new candidate.

Application `ChoiceItems` currently uses an ordinary ListBox. Rows have optional descriptions, padding, minimum 44px height and wrapping, so assuming fixed 44px rows would be incorrect. A future experiment would wrap the timezone ListBox with the supported Virtualizer/ListLayout path, retain the complete logical collection and measure variable rows with supported item-size observation. The existing `.choice-list` max-height/overflow and popover content-sizing/scroll ownership require deliberate inspection; introducing an unconstrained virtual scroll surface can collapse/grow a popup or change width/alignment. Do not virtualize the small theme/date-format selects unnecessarily.

[Root's bounded DOM probe](menu-dom-probe.json), **05:56:06.486Z–05:56:08.345Z**, reports hundreds of mounted options: Chromium **454 options/2,723 descendants**; WebKit **479/2,873**, with 320px client-height and roughly 28–30kpx scroll-height. Both reported query states had the same count, so this is evidence of a large mounted list in those probe journeys, not proof of correct filtering or timing attribution. Local reported elapsed values include their journeys and do not isolate rendering CPU. Counts differ by engine; the earlier Bun-derived 480 collection estimate must not become a fixed browser assertion.

Virtualization remains a higher-risk product change requiring actual timing justification after test batching. Preserve full search/alias/custom-offset availability; empty/no-match states; keyboard Home/End/Arrow/Tab/Enter; hovered-but-unselected blur/Tab behavior; deliberate pointer/keyboard selection; focused option persistence; scrolling to offscreen options; accessible active-descendant/position/count semantics; source/target independence; and small-width long-description geometry. Existing End and alias-selection regressions must retain their final values, not be weakened because an offscreen row temporarily lacks a DOM node. No runtime implementation is proposed for the first batching candidate.
