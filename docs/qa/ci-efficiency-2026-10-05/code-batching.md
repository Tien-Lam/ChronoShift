Installed matcher `node_modules/playwright/lib/matchers/expect.js` computes threshold `Math.pow(10,-precision)/2` and uses strict `<`; precision1 is 0.05, not ≤0.05. Root restored grouped appearance edge arithmetic, preserving the original operands rather than rearranging subtraction near that threshold. Equal infinities have special matcher behavior, but actual browser geometry is finite; this does not remove a reachable layout assertion.

The first prototype lost an implicit missing-layout failure. Original `trigger.boundingBox()` can return null for a layout-less `display:none` element, causing `control.width` to fail when trigger matching applies. `getBoundingClientRect()` instead returns a zero rectangle, allowing the minimum-width check to pass. Installed Firefox bounding-box code explicitly rejects empty client rects; WebKit rejects absent content quads, Chromium requires a box model. Root added `popupHasLayout` and `controlHasLayout` to the coherent snapshot and asserts both true. This closes the identified loss and strengthens the calendar's otherwise bypassed control-width path. Detached/missing trigger handles still fail rather than silently bypassing the check.

The initial popup visibility and horizontal-bounds poll are unchanged. The subsequent geometry/style snapshot is one-shot, as were the old scalar bounds/style assertions; the change does not claim retrying the entire snapshot. For these top-level HTML controls, DOM rectangles use the same viewport space as prior boxes. This would need reconsideration if moved into frames or non-HTML geometry. The snapshot reduces temporal skew among its own reads; appearance and calendar observations retain their prior separate browser reads.

Both themes, three widths, six real menu openings, keyboard Escape, returned focus, selected option/list visibility, source/target contents, calendar bounds/alignment/grid, retained draft/result, page overflow, CSP violations and injected-style checks remain. Success screenshots and normal motion are unchanged. No test/profile is removed, timeout weakened or force-click introduced. ## Native browser alternative requested during this review

A fixed Ubuntu24.04 native runner with the dependency's official browser/OS installation is supported in principle. Installed Playwright recognizes Ubuntu24.04 and maps this exact dependency to Chromium/headless-shell revision1243/version153.0.8010.12, Firefox1543/version155.0, WebKit2359/version26.6. Record actual executable paths and launch/version observations for all three engines; package equality and path existence alone do not authenticate arbitrary restored binary bytes.

The official [Playwright CI guidance](https://playwright.dev/docs/ci#caching-browsers) supports native dependency installation but advises that cache restoration may cost as much as browser downloads, and Linux OS dependencies still require installation. This is a supported alternative, not established faster execution. The historical baseline used the same Playwright1.63.0 and measured install-browser/OS work52s; current container initialization35s is a different environment/sample. Native host rendering may differ even with the same engines, so preserve the four-worker/full258 scenario matrix, profile settings, motion and assertions, and measure actual complete job outcomes.

If prototyped: pin `ubuntu-24.04`, install frozen dependencies with Bun, invoke the local pinned Playwright CLI via `bunx --bun`, install all required OS/browser dependencies on cold runs and OS dependencies on cache hits, and retain executable/version/OS guards and useful failures. Developer runtimes/CLIs remain mise-managed; browser libraries are installed by the official project dependency workflow, not an alternate global runtime manager. If a cached path is used, replace `/ms-playwright` deliberately and check all engines resolve under the intended path. Avoid broad restore prefixes; key by OS release/architecture plus exact dependency/lockfile identity and browser revisions.

[GitHub's cache scope rules](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching#restrictions-for-accessing-a-cache) keep ordinary PR-created caches under the PR merge ref, inaccessible to main/other PRs. Preserve that boundary, trusted producers and least privilege; do not switch to privileged PR triggers or treat an internal cached hash manifest as independent binary authenticity. No cache redesign should change artifact digest/tree checks, trusted successful gate requirements, publishing serialization or fallback. Record cache hit/miss, restore/save/download/dependency costs, cache bytes/eviction and diagnostic-run quota in cold/warm comparisons. Warm-only acceptance hides necessary ongoing costs and cannot establish monthly quota/storage benefit.
