## Wall, thread, sampler and frame attribution

All twelve summary groups independently recompute from the repeated raw rows to floating-point tolerance. Full lists actually report 454 options/2,728 popup descendants, filtered lists two/17, small selects three/22. Repeated full-list operations have more observed scripting than small-select open/close and little layout, supporting a scripting-work investigation. Collection size is not independently varied while holding the widget and all other state fixed: Select and ComboBox have different semantics, and filter/clear also change controlled-input state. It is a plausible collection-lifecycle hypothesis, not a causal count-to-cost estimate or proof that refs, callbacks, overlay positioning or a specific hook is the principal optimization target.

The correct CDP duration-domain enum is `threadTicks`, verified against the official [Performance schema](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/browser_protocol.json). Task/script/layout/style deltas are over the instrumentation's metric boundary, not an additive wall-time partition. The wall window includes input actionability, protocol/evaluate calls, ready assertions and two animation frames. In the sampled run, the metric boundary begins **before** `Profiler.start`, whereas the labelled host action window begins **after** that command returns. The after-metric command and `Profiler.stop` also use different boundaries. Profiling overhead and assertion/injected-selector work therefore prevent direct task/thread/sample/wall comparisons or subtraction into an 'idle budget'. Tracing is enabled even in the repeated non-CPU-sampler run, so those numbers remain instrumented observations rather than an uninstrumented latency benchmark.

The official [Profiler schema](https://github.com/ChromeDevTools/devtools-protocol/blob/master/json/js_protocol.json) defines microsecond intervals between samples, with the first interval relative to profiling start. Independent raw examination finds **50 negative intervals across all 12 CPU profiles**, signed total **−24.015 ms**, minimum **−1.233 ms**. They include synthetic idle/program, app frames and Playwright selector frames. `analyze.ts` currently aggregates signed weights without explicitly flagging these anomalous intervals. Do not silently clamp/repair them or promote net weights to exact nonnegative function time; annotate the limitation while retaining raw samples.

Sampler start/end spans also exceed the labelled window: 1280px small-select-open spans 99.355ms versus labelled 61.815ms; 390px zone-all-close spans 111.840ms versus 61.062ms. First sample intervals are 10.392–36.693ms, large relative to the requested 1ms sampling interval. The report already warns about idle/program/start-stop overhead and sparse noisy weights; this additional negative-interval/boundary fact strengthens that qualification. Sampling records top-stack nodes, not proven exclusive callback CPU costs. Frame counts/time weights, threadTicks and total window latency must remain separate.

The four reported zero-based bundle coordinate mappings are consistent with exact captured code: overlay-position callback at line17/103735, ListBoxItem/useOption/useHover at line17/90602, generic DOMElement render/ref at line11/14194 and React effect cleanup at line7/95235. Installed library code independently matches those shapes. This supports naming observed stack roles, but cannot count lifecycle invocations, allocate all script time to collection code or turn the sparse 7.4ms positioning weight into a portable Linux cost. No regenerated source map or exact exclusive ownership is established.

The raw repeated timeline contains 59,005 events and 72 unique start/end marks for 36 operations. Events span multiple processes/threads and nest/overlap; the analyzer does not wrongly sum them into independent CPU work. Any later trace attribution must pair exact operation marks with the owning renderer/thread and preserve nesting rather than summing browser/compositor events together. Both saved gzip files independently decompress byte-identically: 19,228,390 combined raw bytes, 1,455,262 compressed bytes.

## Close lifecycle and next-step limits

Independent close-record recomputation agrees with the report: early-entry removal at 171.2/156.9ms, entry finished 1.8/1.1ms before actual DOM removal; settled removal 5.9/7.7ms. Post-removal assertion observation adds 10.3/33.1ms early and 2.8/3.0ms settled. The observer records actual absence of the popup, not merely `isVisible` change. Installed `useExitAnimation` obtains current element animations and waits for their finished promises before its closed state unmounts Popover. Thus normal entry-lifecycle waiting explains this bounded local close difference; hundreds of milliseconds of layout/script work do not.

These are two early/two settled observations, not a policy to change animation or guarantee event-based test savings. The observer start precedes Escape dispatch and includes protocol delay. Moving a wait before Escape changes where time is observed. An event-based test observation would still need the same actual hidden/removed/focus invariant and retains real animation lifecycle time; it cannot justify skipping motion, force-clicking, dropping expectations or inferring a whole-run quota reduction.

The report correctly proposes only counting/narrowing lifecycle work before a matched local experiment. There is no implemented candidate. Retaining all 454 options, exact search/custom-offset/alias behavior, accessible descriptions, wrapping, focus/ownership and normal-motion interactions is a necessary scope condition, not yet a regression result. A local timing boolean or these stack roles alone authorizes neither a source candidate nor another hosted sweep. Evidence of Linux gain would require a concrete correct candidate and comparable full-gate conditions; neither exists here.

The report's explicit no-target-completion/no-phone-p95/no-historical-diagnosis conclusions are warranted. Approve the descriptive profile with the sampler caveat above; keep optimization, TIE-375 and historical/physical acceptance unapproved.
