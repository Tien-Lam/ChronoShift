# Dropdown alignment (TIE-343)

Original report: the theme dropdown looks misaligned and all dropdowns look different. The report did not identify a browser version, screenshot, elapsed timing, cache history or whether it meant the closed control or native popup.

Base: `7c41d51035d761b331fec3f082c2d897baa30e81`. Candidate: `18b8a1dee8f8d5af04bc1f6352fb697ce66ba300`. PR: https://github.com/Tien-Lam/ChronoShift/pull/28. The actual independent reviewer brief is saved in the PR description. The original implementation rendered different heights and native insets: IAB at 578px measured selects 44.5px, timezone inputs 46px, date 48px.

The shared shell standardizes height 44px, font 16px/line 24px, start padding 12px and end padding 40px for choices, with a matching decorative chevron. The date control keeps its native calendar icon. Appearance content has even 16px padding and right-aligns to its trigger with 8px gap. Convert and target input share a grid row; help text no longer changes button alignment. Selects and searchable datalists retain distinct native interaction semantics.

Research: [Radix Themes Select sizing/variants](https://www.radix-ui.com/themes/docs/components/select) and [Radix spacing](https://www.radix-ui.com/themes/docs/theme/spacing), [Radix typography](https://www.radix-ui.com/themes/docs/theme/typography) and [WAI combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). The convention applied is shared visual size, spacing and typography while retaining native editing/selection behavior. Browser/OS option-popup appearance remains platform-controlled.
