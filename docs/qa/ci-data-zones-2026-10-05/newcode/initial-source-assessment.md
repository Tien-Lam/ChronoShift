## Independently derived failure paths

1. **Shared collection integrity and filtering.** Full nodes, option values, child arrays and props are frozen; module construction supplies every original ID/text/order before either field opens. The private Map is not runtime-frozen by Object.freeze, but is inaccessible through normal public collection methods and no application writer exists. Locked useCollection returns the supplied collection without running its builder. Locked useComboBoxState filtering spreads item nodes into clones before ListCollection rewrites prev/next/index; therefore filtered source traversal cannot rewrite target/full traversal. Empty/few/full filter transitions and manual full opening need runtime verification, including first/last neighbor boundaries and offscreen keyboard focus.

2. **State ownership and render closure.** Shared render closures capture only frozen option data. Each ZoneChoice owns its hook call, refs, selected/input state and current-value dedup ref. Each mounted ZoneRow consumes the ListStateContext republished inside RAC ListBoxInner, which derives its selection manager for the displayed collection. useOption receives that derived state rather than the sibling field or module collection state. Row label/description props are applied directly to public Text components; no inherited ComboBox TextContext exists in this custom bridge. Need runtime ID linkage, selected/current alias identity, active-descendant and source/target isolation checks.

3. **Controlled commits and cancellation.** Input and selected key are both controlled, selected key is null for custom/empty text, and selected text is original ID as in baseline. The commit callback updates current.current before onChange, suppressing duplicate sequential completion. useComboBoxState owns Enter/Tab/revert/blur handling and retains its last collection during dismissal; no new async completion/retry/timeout owner is introduced. Existing App callbacks update prefs and invalidate conversion. Input changes, deliberate selection, ordinary blur, Escape, reset and external preference changes can each expose stale hook state; test final values after the complete transition, not transient debounce state. Existing App spread-prefs closure remains unchanged.

4. **Public context bridge and native input/trigger semantics.** Imports are through publicly exported subpaths; no application private import or cast found. InputContext merges hook callbacks with diagnostic onFocus using RAC useContextProps. ButtonContext similarly retains native press-start/manual-open while diagnostic onPress is merged. GroupContext supplies actual geometry ref and computed invalid state. Popover uses the existing public trigger/overlay owner with native entry/exit and scroll dismissal, and clears the input/button/group contexts inside popup. Its anchor is the real Group, so no fallback input-only width observer is needed for this usage. No new geometry animation or focus wrapper exists. Wrapper aria-label duplication has been removed. Need normal-motion focus/blur/trigger/More options keyboard operation, generated IDs and invalid ARIA checks; source input is intentionally not given target invalid semantics by unchanged App.

5. **Full row behavior.** Row structure/CSS/check icon/44px natural minimum match baseline. Public useOption supplies option/key/selection/virtual-focus/press behavior, and useHover supplies styling without overriding shouldFocusOnHover=false. Nonvirtualized options are all rendered and need no explicit aria-posinset/setsize (native complete DOM order supplies position); compare these attributes against baseline. Missing RAC per-row useKeyboard/useFocus callbacks are immaterial to current rows because the original row supplies neither user callback. No links, actions, drag/drop, disabled rows or sections exist in this application collection; generic ChoiceSelect remains unchanged.

6. **Lifecycle and privacy.** Collection module initialization is deterministic from existing timezone tables; row hooks mount with rows and hook-level observer cleanup remains library-owned. Unchanged App worker, offline/update, reset and import owners retain their original behavior. No input text is added to network, permanent storage or diagnostics. This review does not establish SSR compatibility: App already accesses browser APIs and the app is client-only. StrictMode/runtime mounted lifecycle remains untested. No changes to CSP/assets/manifest paths are introduced in source, but served diagnostics/build integrity need runtime checks.

7. **Dependency/notice ownership.** New direct imports require exact direct package declarations before adoption/final gate. They are only transitive in current package.json. Existing notice generator traverses production dependencies, and the existing notice file already contains both locked packages; final frozen install/build must verify the direct declarations and generated notices.
