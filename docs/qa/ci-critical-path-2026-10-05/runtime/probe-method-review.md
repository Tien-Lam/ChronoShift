## Matched conditions and provenance

The driver serially runs baseline/candidate/candidate/baseline phases. Each phase gets an owned fresh localhost origin; Chromium, Firefox and WebKit each launch a separate browser and run six fresh contexts. Contexts match en-AU locale, Australia/Sydney timezone,900×640 viewport and1× raster. Each context starts without previous context's cookies/local storage/service-worker registration. Test server mode is explicitly0, so the unchanged same-origin server cannot supply fault-release variants. Source provides no motion override, forced interaction, screenshot, trace stylesheet injection or competing browser work. Context/browser/server creation and termination are outside row timing windows. Ordinary application motion is inherited; the script does not independently assert the media-query value or animation duration.

ABBA balances one fixed version ordering across the four phases. Browser engine order remains Chromium→Firefox→WebKit in each phase. All six contexts per engine/phase share one running browser, while OS filesystem/disk/cache state survives the whole experiment. Therefore "cold" means fresh browser context/storage and fresh-origin install, **not cold machine, cold filesystem, fresh process for every sample or representative Linux contention**. First/cold and later/warm context samples should all remain in summaries; do not select only favorable rows.

`inventory()` recursively hashes every regular build file before launching any browser and rejects non-regular members. The retained original has14 members per artifact. Main JS names/hashes differ, CSS and worker hashes match, HTML/SW hashes differ, and release marker is identical. Candidate review brief explicitly states both artifacts use the base SHA in the release identifier; that common SHA alone cannot distinguish candidate implementation. The full inventories can distinguish artifact bytes. Each accepted row also records the HTML module script path. However, the probe itself neither hashes actual served responses nor repeats inventories after the run; it does not cryptographically prove that browsers received all inventoried bytes or that disk bytes stayed unchanged. Root's frozen-source/build ownership is separate provenance, not a claim established by this method alone.

The method sets Bun server cwd to the appropriate frozen runtime dist directory while executing the unchanged root server source. It waits for the printed origin before measuring and awaits the owned process's exit on SIGTERM. Normal and failure paths reach the outer stop/write finalizer; browser launch succeeds before an inner browser-close finalizer is installed, and browser.close releases contexts if a row fails. No post-exit fetch is performed, so server-exit observation is supplied by the awaited process, not a separate unreachable-origin probe. The explicit source calls spawned `bun` via the parent environment; root should preserve the mise invocation/runtime version rather than imply independent subprocess-runtime attestation.

## Time scopes

- **readyMs**, lines93–99: host `performance.now()` before `page.goto`, after the main offline-ready attribute assertion returns. Default goto waits for the load event. This includes application loading/startup, first offline install/probe, protocol overhead and assertion observation/backoff. It is neither exclusive hidden collection initialization nor actual readiness-transition timestamp. Navigation-entry `domInteractive`, `domComplete` and `loadEventEnd` are separate browser timing records relative to that navigation; they cannot be directly subtracted from host timestamps.
- **firstConversionMs**, lines110–118: host interval covering native message fill and two ordinary locator expectations. The real250ms debounce and module worker remain active. It includes polling observation after output completion and does not arm or timestamp the actual pending/settled DOM transition. Previous retained ordinary expectations had substantial backoff variance; a faster assertion finish in this window cannot alone establish faster renderer completion.
- **firstOpenMs**, lines119–126: host interval covering native summary Enter and source-input visibility assertion. Visibility establishes expansion/mounted visible field, **not completed native motion, completed collection construction across all controls, paint completion or CPU cost**. The probe then fills the source field, but that later operation is outside firstOpenMs.
- **row began/ended**: real UTC observations surround the longer navigate→conversion→source-edit→close→reopen journey. End is captured before the final module-script attribute read and context.close. These UTC clocks are not precise CPU windows. **top-level started/ended** include artifact inventory, browser/server/context setup, all phases and cleanup, with JSON serialization/write happening after the final clock. They should not be labeled sum of application runtime.

The three host duration windows are sequential and non-overlapping, but their sum omits navigation-record readback, source editing, closing/reopening and setup/cleanup. Summing them is at most a selected-journey wall subtotal, not full runner/browser-suite time. No CPU/thread counter or profiler exists in this driver. Browser-process/server setup and the older control's page-create cost cannot be attributed as saved application work from these windows.

## Oracles and lifecycle coverage

The fixed input `April 9, 2026 3pm UTC`, fresh Australia/Sydney device timezone and independent1:00am / 10 Apr 2026 expectations preserve output identity across variants; expected values are not derived from the app. No prior output exists in a fresh page, so stale prior output cannot satisfy this particular first conversion. Regexes allow locale Apr/April variation and are not fully anchored. It checks time/date, but lacks separate zone/result-count/source-label assertions. That bounded oracle is adequate to prevent an empty/obviously wrong output from passing the timing journey; it is not conversion-corpus or all-displayed-semantics acceptance.

Source field is filled with canonical Asia/Tokyo, Tab commits, close verifies hidden, reopen verifies the same input value. This covers one native keyboard toggle sequence and committed source-string persistence. It does **not** establish all candidate invariants:

- First opening waits for visibility before the next action; immediate Enter/Space→Tab/typing is unexercised.
- Date partial segments, invalidity across close, blocked conversion while incomplete, complete-date retention and reset/remount ownership are unexercised.
- Canonical source text could survive a remount because parent prefs owns it, so its persistence does not alone prove child/local-state retention.
- Rapid coalesced native toggles, resize/theme while closed, source popup/calendar ownership on close, deliberate option selection and post-reopen result identity are unexercised.
- Errors are checked once before row capture/last script read/context cleanup. Empty page-error lists establish that bounded check, not CSP/privacy/screen-reader/physical-device validation. No console/CSP/network observation is collected.

The candidate's source-only reviews and later separately owned lifecycle journeys must establish these gaps. Root's initial probe demonstrates an available first-open source control under an awaited visibility guard, not race-proof immediate Tab behavior.
