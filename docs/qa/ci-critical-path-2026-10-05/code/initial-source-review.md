## Independently derived paths

- Native details is uncontrolled, initially closed. Its toggle handler reads current open state and makes a monotonic false→true latch. A queued open/close sequence coalesced to closed does not mount; a final open mounts. After any first successful open, subsequent closes cannot unmount option-fields or erase React Aria's partial segments, inputReset, calendar state, or ComboBox state. Reset alone increments referenceReset and deliberately recreates DateChoice. Ordinary parent renders and viewport resize retain the same subtree identity.
- Native toggle dispatch occurs after the open state mutation. Mounting therefore creates a potential first-open interaction boundary that the eager base lacks: immediately following keyboard Tab might arrive before option-fields exists. This is a hypothesis requiring real browser keyboard dispatch and value/focus evidence, not an established blocker. React's installed event priority table treats toggle as discrete, but that cannot remove the native pre-dispatch interval. Tests must avoid waiting for the source input before Tab.
- First DateChoice value is always blank: App has no stored reference-date restoration, and referenceValid/referenceValidity both initialize true. Its year-segment effect reports true and referenceValidityChanged short-circuits; first opening consequently should neither invalidate a settled result nor restart/cancel a pending conversion. Source preferences load independently before option mount; source zone validity is derived in App even while hidden. DateChoice does not autofocus; summary remains the first-open focus owner. No new promise, observer, timer or worker lifetime is introduced by the latch.
- Subsequent partial date input reports false, clears displayed results and increments request before terminating the current worker. conversionRevision/referenceValid drive cleanup and a new debounce; the 250ms handler refuses to start a worker while invalid. Retained stale onmessage/onerror closures check the request identity and current worker. Closing More options does not restore referenceValid because the component is retained. Completing/clearing/resetting a date restores validity explicitly. The unchanged DateChoice effect timing needs a late-completion test around a partial edit rather than assuming a final alert alone proves stale result rejection.
- Reset updates both validity ref/state and reference date before incrementing the key and invalidating. Mount's blank-valid report is then idempotent. Source/target/date-order/time-format preferences remain parent-owned; options close has no save/reset effect. First mount's controlled zone value must be tested against stored non-default preferences to exclude a React Aria mount normalization callback that changes a value or cancels existing work.
- Copy focus intent listens for native keydown/pointerdown/focus at document capture. New first-open interaction supersedes a delayed manual-copy focus callback; option mounting itself contains no autofocus. Opening must not be used as an excuse to reacquire focus after a delayed rejection test. Import ownership increments only on invalidate; opening a control without editing currently does not claim draft ownership, consistent with the eager base.
- All Choices imports and timezoneOptions/search maps are still evaluated at module load because target ZoneChoice remains mounted and uses them. The candidate avoids the hidden source collection/control instances; it does not prove deferred JavaScript download, smaller immutable assets, or avoided timezone module construction.
